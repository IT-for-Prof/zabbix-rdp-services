# zabbix-rdp-services

> 🇬🇧 [Read in English](README_EN.md)

Мониторинг **RDP** по лучшим практикам для Zabbix 7.0 — TLS-сертификат, принудительный
NLA, набор протоколов TLS и доступность — в виде внешней проверки и улучшенного
шаблона `Template App RDP Service` (templateid 11501). Сопровождается компанией
[IT for Prof](https://itforprof.com).

## Зачем скрипт

RDP отдаёт свой X.509-сертификат только **после** согласования X.224/RDP
(`PROTOCOL_SSL`/`PROTOCOL_HYBRID`). Обычное TLS-рукопожатие (например,
`web.certificate.get` у Zabbix Agent 2) на порту 3389 **не работает**. Поэтому
`rdp_check.py` сам выполняет согласование [MS-RDPBCGR] на чистом Python
(stdlib `socket`/`ssl` + `cryptography`, без сторонних RDP-библиотек) и затем читает
сертификат / NLA / TLS.

## Что мониторится

| Уровень | Как | Метрики |
|---|---|---|
| Доступность | нативный `net.tcp.service[tcp,,{$RDP_PORT}]` | порт доступен + задержка |
| Сертификат / NLA / безопасность | `rdp_check.py cert` (1ч) → JSON-мастер + зависимые элементы (JSONPath) | срок действия, издатель, самоподписанный, совпадение имени, валидность цепочки, тип/размер ключа, алгоритм подписи, действителен сейчас, версия/шифр TLS, уровень безопасности, NLA |
| Набор TLS | `rdp_check.py tls-scan` (1д) + LLD `discover-tls` | число слабых протоколов + обнаруженные элементы/триггеры по каждому протоколу |

**Логика доверия:** сертификаты доверенных CA проверяются полностью (цепочка + имя +
срок); самоподписанные сертификаты по умолчанию не поднимают тревогу по
«самоподписанности»/несовпадению имени (`{$RDP_CERT_ALLOW_SELFSIGNED}=1`), но срок /
NLA / TLS / рукопожатие проверяются всегда. Триггеры зависят от «порт недоступен» и
«проверка не проходит», чтобы при сбое поднималась одна корневая причина.

## Структура

```
scripts/externalscripts/rdp_check.py   # cert / tls-scan / discover-tls / self-test
scripts/deploy/install.sh              # venv через uv в /opt/rdp_check + установка в ExternalScripts
templates/rdp-service/template_11501.yaml          # улучшенный 11501 (источник истины)
templates/rdp-service/template_11501_baseline.yaml # исходный, без изменений
tests/                                 # pytest: байтовые/сертификатные фикстуры + фейковый RDP-сервер
docs/                                  # спецификация, план, валидация, аудит, ревью, заметки по развёртыванию
```

## Развёртывание

Запускать на сервере Zabbix **и на каждом прокси**, который мониторит RDP-хосты
(совпадение egress):

```
sudo sh scripts/deploy/install.sh          # создаёт venv /opt/rdp_check, ставит rdp_check.py
```

Затем импортировать `templates/rdp-service/template_11501.yaml`
(createMissing + updateExisting, **deleteMissing: false**) — сначала просмотрев diff
через `configuration.importcompare`.

## Макросы

| Макрос | По умолчанию | Назначение |
|---|---|---|
| `{$RDP_PORT}` | `3389` | TCP-порт RDP |
| `{$RDP_TIMEOUT}` | `30` | общий бюджет времени на проверку (timeout элемента должен быть больше) |
| `{$RDP_HOSTNAME}` | *(пусто)* | имя для сверки с SAN/CN сертификата; пусто = брать адрес подключения |
| `{$RDP_CERT_EXPIRY_WARN}` / `_CRIT` | `21` / `7` | пороги «дней до истечения» |
| `{$RDP_CERT_ALLOW_SELFSIGNED}` | `1` | 1 = самоподписанный это норма; 0 = тревога |
| `{$RDP_CERT_EXPECT_CA}` | `0` | 1 = тревога, если сертификат не доверен CA (цепочка невалидна) |
| `{$RDP_CERT_MIN_RSA_BITS}` / `_EC_BITS` | `2048` / `256` | пороги слабого ключа |
| `{$RDP_NLA_ENFORCE}` | `1` | 1 = тревога, если NLA не принудительный |

## Подводные камни (проверено на практике)

- В ключах элементов используется **`{HOST.CONN}`** напрямую — Zabbix **не** раскрывает
  встроенный макрос, если он лежит *значением пользовательского макроса*. Поэтому у
  каждого хоста должен быть интерфейс.
- Триггеры **вложены в свой первый элемент** (`items[].triggers[]`); блок `triggers:`
  на уровне шаблона при импорте в 7.0 отклоняется.
- `cryptography >= 42` для аксессоров `not_valid_*_utc` (для 41 есть шим).
- При переборе версий TLS нужно подавлять `DeprecationWarning` (TLSv1/1.1), иначе текст
  предупреждения утекает в stdout и портит JSON, который разбирают зависимые элементы.
- RD Gateway (RDP-через-HTTPS:443) — **не** задача этого шаблона: для его
  сертификата/TLS используйте шаблон веб-сервисов, а внутренние TS-хосты мониторьте напрямую.

Разработка: `pip install -r tests/requirements-test.txt`; `pytest tests`;
`ruff check scripts tests`; `mypy --strict scripts/externalscripts/rdp_check.py`.
